# Image Order — 영구 고정 목표 및 개발 연속성 규약

이 문서는 사용자가 처음부터 정한 목표를 보존한다. 개발 단계가 바뀌거나 세션이 이관되어도 목표를 재해석하거나 축소하거나, 사용자에게 재설명하게 하지 않는다.

## 최종 목표 (변경 금지)

**Android의 어떤 앱과 웹사이트든 이미지 업로드가 시작되는 상황에서 Image Order를 자동 실행하거나 선택 팝업에서 선택할 수 있어야 한다. 우리 앱은 순정 갤러리처럼 자연스럽고 단순하게 동작해야 하며, 사용자가 이미지를 누른 그 순서가 외부 업로드 과정 전체에서 정확히 유지되어야 한다.**

- 사용자의 동선은 **사진 첨부 → 갤러리에서 순서대로 사진 선택 → 첨부 완료**, 하나뿐이다.
- 사진의 **원본 바이트, 해상도, 화질, 색상, 형식, 메타데이터, 파일명**은 바꾸지 않는다. 사진에 번호 인쇄/병합/재인코딩/강제 리네임으로 순서를 우회하지 않는다.
- 순서는 파일명, 확장자, 수정시간, 가져온 순서, OS의 임의 정렬에 의존하지 않고 **사용자 선택 순서**만 기준으로 한다.
- 앱/사이트 전용 패치보다 **Android 전반의 이미지 첨부 경로**를 우선 조사·검증·확장한다. 가능한 인터셉션 방식은 실기기에서 실제 업로드 연결까지 증명한다.
- 하나의 일관된 갤러리 UI를 제공한다. 메뉴 여러 개, 우회 방식 여러 가지를 사용자에게 떠넘기지 않는다.
- 특정 Android API·시스템 권한에서 직접 가로채기가 막힐 때 이를 완료로 간주하지 않는다. OS 연동, 호환 경로, 허용되는 심화 방식 등 기술적 대안을 탐색한다. 기능의 실제 성공 범위와 미완료 범위를 분리해 기록한다.
- Android 설치가 막히는 과도한 권한, Play Protect 차단, 기존 사용자 업데이트 인증서 불일치는 회귀 결함으로 취급한다.

## 2026-11-27 — 사용자 재확인: 첫 번째 사진 선택창 우선

- 목표는 **사진 첨부 버튼 → 최초 사진 선택창(Image Order 또는 순서 지정이 가능한 공통 연동 UI) → 순서 선택 → 첨부 완료**다. 매번 파일 앱, Browse, 공유, 재선택 등 추가 절차를 요구하면 핵심 합격이 아니다.
- GPT, Chat LLM, 네이버 리뷰의 공통 시스템 사진 선택창은 일반 이미지 첨부의 대표 검수 사례다. Chrome/Claude의 파일·사진 혼합 첨부는 별도의 호환성 사례일 뿐, 특정 서비스 UI를 제품 구조 또는 전체 합격 기준으로 삼지 않는다. 네 사례 중 세 사례에서 공통 화면을 관측했다는 것이며 전체 시장 비율을 추정하지 않는다.
- 특정 앱 전용 분기나 그 UI를 따라가는 테스트에 개발 우선순위를 빼앗기지 않는다. 최초 선택 요청 계약과 실제 시스템 picker의 실행/결과 경로를 중심으로 연구한다.
- P0: 직접 사진 첨부의 최초 선택창 진입/선택 순서/원본 반환. P1: 기존 GET_CONTENT/PICK 호환성 유지. P2: 혼합 파일 첨부 및 DocumentsUI 편의성. P2 성공을 P0 성공으로 보고하지 않는다.
- Android 기본 설치 환경과 명시적 시스템 수준 설정이 필요한 실험을 구분한다. 일반 사용자용 APK의 권한·설치 안전성, 기존 서명, 원본 무변경을 유지한다. 기술적 가능성은 독립 테스트 앱의 패키지 비고정 실제 첫 호출 및 결과로 확인한다. 우회 동선을 새 목표로 바꾸지 않는다.

## 작업 명령의 의미

사용자가 **"진행"**이라고만 말하면, 설명이나 목표 확인 요청 없이 **그 자리에서 직전 개발 상태를 복원한 다음 다음 미완료 개발·검증 단계**를 실제 수행한다. 코드 수정, 테스트, GitHub CI, 정식 서명 APK 배포를 가능한 범위에서 진행하고 테스트 결과와 산출물을 보고한다.

사용자가 **세션 이관**을 요청하면 기존 목표, 이전 작업과 검증 기록, 소스 브랜치, 배포 주소, 서명 및 CI 구조, 미해결 결함을 가능한 한 완전히 복원한다. 신규 세션이라고 목표를 다시 질문하지 않는다.

중간 버전은 종착점이 아니다. 최종 목표에 실질적으로 가까워지는 기능만 우선 구현한다. **실제 외부 앱에서의 선택 → 반환 → 업로드 순서**를 검증 없이 성공으로 홍보하지 않는다.

## 합격 기준

1. 여러 앱·브라우저·웹사이트의 서로 다른 첨부 방식에서 한 가지 동일한 갤러리 UX가 호출되는지 실기기로 검증.
2. 사용자 지정 1,2,3,4,5 순서의 원본 이미지가 실제 업로드 후에도 동일한 순서로 인식·배치되는지 엔드투엔드 검증.
3. 첨부 전·후 이미지별 원본 바이트 SHA-256 동일성(수신측 변환이 있는 경우 어디서 생겼는지 구분).
4. 단일/다중 첨부, HEIC·PNG·JPEG·WebP, 동명 파일, 중복 선택, 대량 선택, 프로세스 복원, 저장소 권한 변경, 반복 열기 테스트.
5. APK 서명 연속성, 설치·업데이트, Play Protect 경고 여부 및 GitHub 릴리스 다운로드 무결성 검증.

**핵심:** 사용자에게 목표를 다시 설명하게 하거나, 설치·갤러리 화면의 부분적인 성공을 최종 목표 달성으로 오해하지 말 것.

공식 이름은 **Image Order**다. 개발 브랜치는 `image-order/dev-v2`로 분리한다. 기존 소스 경로, 패키지 ID `com.twobornot.imageorder`, 서명 인증서, 기존 공개 APK 다운로드 URL은 업데이트 호환성을 위해 유지한다.
