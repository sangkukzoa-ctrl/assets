## Direct source research and candidate code changes
### Forge 1.20.1 post-login C&B RGB light:
- Official C&B 20.1.20 branch `version/1.20.1`: a LIVE change sends `TileEntityUpdatedPacket` -> `mod.chiselsandbits.network.handlers.ClientPacketHandlers.handleTileEntityUpdatedPacket(BlockPos,CompoundTag)` -> `ChiseledBlockEntity.handleUpdateTag/load`, which **deserializes NBT asynchronously**. The port previously adapted 26.x `receivePayload` Mixin, which does not match 20.1.20's client update path, and had only startup/initial-sculpt C&B tests. Existing C&B source reader and RGB light engine work with a fully-loaded fixture, but do not automatically observe all live C&B data changes.
- [Forge builder `3bbc0f2a`](https://github.com/sangkukzoa-ctrl/assets/commit/3bbc0f2a3332fb83f1b43e2dad075b97985a0451): generates a **Forge-only optional** `@Pseudo` Mixin on the actual client packet handler, queues `RGBRealLightEngine.refreshCnbBlockEntity()` on client thread. Optional C&B not a new hard dependency.
- [Forge builder `c077573a`](https://github.com/sangkukzoa-ctrl/assets/commit/c077573a07dbf552d2cf8a499a8787c8acf45aeb): prevent reading OLD voxel stats during async C&B decompression: client-local, per-position and per-world sequence-guarded follow-ups at 0/200/650/1500/3000ms. This safely allows RED/GREEN or GLOW changes to be observed in AUTO and MANUAL replay.

### NeoForge 1.21.1 (and Forge) vanish of C&B mesh under repeated remote bakes:
- Original shared `RGBCnbGeometryBakeDebouncer` cancels rapid C&B model rebuild calls, but lacked a guaranteed trailing/final async model rebuild, allowing a stale or EMPTY model to survive even when real C&B microbit stats and RGB source cache were intact. [Shared source fix](https://github.com/sangkukzoa-ctrl/assets/blob/rgb-blocks-legacy-compat-audit/rgb-blocks-compat/recovered/fabric/com/rgbblocks/client/cnb/RGBCnbGeometryBakeDebouncer.java) registers a debounced trailing rebuild of the exact CURRENT C&B block entity, with world-identity, tile-identity, and request generation checks. Never changes light or voxel state.
- [Bounded missing-mesh watchdog `1e822ad4`](https://github.com/sangkukzoa-ctrl/assets/commit/1e822ad49ed5c9a4f8b79ea9683e193a24e9d998) and [RGB engine hookup `ebb21e5c`](https://github.com/sangkukzoa-ctrl/assets/commit/ebb21e5c312530c95d6b0854863ec38927112e88): client checks at most 12 actual loaded glowing C&B sources every 40 ticks, only after RGB light persistence ready; if nonair bit statistics remain present while Scena's REAL baked model has zero quads for three consecutive observations, rebuild THIS block's model only, throttle to once per 600 ticks/position, NEVER edit tile bits, native world save, RGB section light or other blocks. No class-load dependency on C&B or Scena when not installed.
- Shared real Java source `rgb-blocks-compat/recovered/fabric/com/rgbblocks/` is used to build **BOTH** native versions, while Forge-only compatibility injections live in `rgb-blocks-compat/build_mc1201_forge.py`. The archived `recovered/neoforge` is NOT the compiled input.
